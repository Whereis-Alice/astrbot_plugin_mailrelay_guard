# QQ 掉线通知

QQ 连接断开后，机器人无法通过同一个 QQ 连接告诉你。本插件会改用 SMTP 邮件通知。

## 开启步骤

1. 配好 SMTP，在邮件中心的运行概览中点击「测试连接」。
2. 打开「掉线守护」，填写接收通知的邮箱。每行一个；留空使用主人邮箱。
3. 保持监控平台为 `aiocqhttp`，适用于 NapCat 和 LLOneBot。只监控指定连接时填写 AstrBot 中该平台的 ID。
4. 点击保存，再点击「发送测试通知」，确认邮件能收到。
5. 开启掉线通知并保存。确认页面显示被监控的 QQ 账号。

也可以直接在 AstrBot 插件配置中编辑下面的配置。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `enable_offline_notifications` | 关闭 | 开启自动检测 |
| `offline_notify_recipients` | 空 | 每位邮箱独立投递；留空使用主人邮箱 |
| `offline_monitored_platforms` | `aiocqhttp` | 平台类型或平台 ID 列表；空列表不监控 |
| `offline_check_interval_seconds` | 180 | 每轮检测间隔，范围 30–3600 秒 |
| `offline_failure_threshold` | 3 | 连续检测失败达到此次数才告警，范围 1–10 |
| `offline_notify_on_recovery` | 开启 | 恢复连接后通知，并显示掉线时长 |

例如设置每 60 秒检测、连续失败 3 次，会在约 2–3 分钟的持续异常后确认掉线；检测或 SMTP 超时会增加实际时间。短暂网络波动不会立刻通知。持续离线只发一次状态通知，恢复后可再次告警。

投递失败时，只重试未成功的收件人，最多额外重试 3 次，间隔与检测周期相同。SMTP 接受表示邮件服务器已接收，不保证邮件最终进入收件箱。

## 掉线概览

打开「掉线守护」即可查看，不需要额外配置。

- 时间范围可选最近 24 小时、7 天、30 天，也可以只看某个 QQ 账号。
- 折线展示各区间累计掉线时长。悬停、Tab 聚焦或手机点选可查看时间、时长和涉及事件数。
- 时间轴分别显示在线、确认掉线、疑似异常和未知状态；斜纹空白代表没有观测。点击色块可查看区间与原因。
- 事件列表可展开查看原因、确认时间和恢复时间。「未确认恢复」不代表当前一定离线；「观测中断」也不代表已恢复。

只有达到连续失败阈值的异常才算掉线事件，确认后会回溯到本轮连续失败的第一次检测。未达到阈值的短暂异常仅显示为疑似异常。图表时间精度取决于检测间隔，不是 QQ 客户端的精确断线日志。

**统计口径**：累计时长按所选账号相加，多账号可能超过范围本身的时长；最长时长只统计当前范围内单次事件已观测到的掉线时间。在线占比仅按已确认的在线与掉线时间计算，观测覆盖则告诉你整个范围内有多少账号时间可用于统计。未知状态、疑似异常和监控空白均不计入在线或掉线。趋势按滚动区间分组，24 小时按小时，7 / 30 天按 24 小时，并非自然日。

历史保存在 AstrBot 插件数据目录的本地 SQLite 数据库中，插件重载不会清空。最多保存 90 天、50,000 个状态区间和 10,000 次事件，达到限制后优先淘汰旧记录；事件列表仅展示当前范围内最近 100 次，统计仍使用范围内保留的全部数据。不采集安装前或监控关闭期间的历史。关闭监控只停止采集，不删除已有记录。

页面每 15 秒自动更新；正在查看图表、展开事件或编辑设置时不会打断操作，随时可点击概览中的「刷新」。本地历史写入失败不会阻止掉线邮件发送，存储不可用会在页面提示。

## 模板

掉线与恢复分别有主题和 HTML 正文，可在邮件中心直接编辑、预览并测试。默认掉线用红色提醒卡片，恢复用绿色卡片；也附带纯文本正文供不支持 HTML 的邮件客户端阅读。

| 变量 | 内容 |
| --- | --- |
| `{{nickname}}` | 机器人昵称，获取不到时用 QQ 号或“QQ 机器人” |
| `{{bot_id}}` | QQ 账号 |
| `{{platform}}` | 平台类型 |
| `{{time}}` | 通知生成时间（AstrBot 所在服务器的本地时间） |
| `{{reason}}` | 检测到的断线原因 |
| `{{downtime}}` | 本次掉线时长，主要用于恢复通知 |

模板变量会按邮件正文安全转义，邮件主题中的换行会被折叠。只应由管理员编辑 HTML 模板。页面预览禁止脚本、外部资源和表单，不会加载模板中的远程图片。

## 检测范围

检测 OneBot 反向 WebSocket 是否连接，并调用 `get_status` 判断 QQ 账号是否在线。接口不支持时用 `get_login_info` 复核；无法判断的异常不会直接认定离线或恢复。同一个连接的多个 QQ 账号分别检测，不会因另一个账号在线而掩盖断线。

AstrBot 和插件必须保持运行，SMTP 网络也必须可用。如果整个 AstrBot、服务器或网络停止运行，本插件不能发送通知，需另配外部监控。实时告警判定保存在内存中，插件重载会重新开始判断，但已采集的历史仍保留；被管理员禁用或移除的平台不再监控。其他类型的平台如果没有 OneBot 状态接口，不保证支持。
